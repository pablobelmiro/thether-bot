01

Requisitos

Tether se ejecuta en el mismo equipo que Claude Code. Esa máquina necesita:

  • Linux o macOS. Windows no es compatible.
  • Node.js 22.13 o superior. Con nvm: nvm install 22.
  • tmux y curl. apt install tmux o brew install tmux.
  • Claude Code, instalado y con la sesión iniciada. Ejecuta claude una vez en una terminal para comprobar que funciona.
  • Una cuenta de Telegram, si quieres usar el bot. El panel funciona sin ella.

No necesitas una clave de API. Tether usa tu sesión local de claude.

02

Instalación

Terminal
$ git clone https://github.com/pablobelmiro/thether-bot.git
$ cd thether-bot
$ ./install.sh

El instalador:

  1. comprueba los requisitos (sistema, versión de Node, tmux, curl, claude);
  2. instala las dependencias y compila el proyecto;
  3. enlaza el comando tether en ~/.local/bin;
  4. ejecuta tether setup: añade los hooks de Tether y el reenviador de la línea de estado a ~/.claude/settings.json (con una copia de seguridad), añade reglas de denegación que protegen tus secretos y agrega una línea a ~/.claude/CLAUDE.md para que Claude formatee bien las respuestas para Telegram;
  5. en Linux, ofrece ejecutar Tether como un servicio de usuario de systemd que arranca solo y se reinicia si falla. Reiniciar o detener el servicio no detiene las sesiones de Claude en marcha.

Opciones del instalador

OpciónEfecto
(ninguna)Interactivo: pregunta antes de instalar los hooks y el servicio.
--yes, -yAcepta todas las opciones por defecto (hooks y servicio) sin preguntar.
--no-hooksNo toca ~/.claude. Ejecuta tether setup más tarde: sin los hooks, Tether no puede ver tus sesiones.
--no-serviceNo ofrece el servicio de systemd. Arranca Tether tú mismo con tether.
-h, --helpMuestra el modo de uso.
PATH

Si el instalador avisa de que ~/.local/bin no está en tu PATH, añade export PATH="$HOME/.local/bin:$PATH" al perfil de tu shell y abre una terminal nueva.

Si instalaste el servicio, Tether ya está en marcha. Si no, arráncalo con tether y deja esa terminal abierta. Después abre http://127.0.0.1:4100 en un navegador del mismo equipo.

03

Asistente inicial

Hazlo cuanto antes

Hasta que definas una contraseña, la página de configuración está abierta a cualquier cosa que pueda llegar a 127.0.0.1:4100. Completa el asistente justo después de instalar. En un equipo compartido, detén el servicio hasta hacerlo.

La primera vez que abres el panel, un breve asistente te pide cuatro cosas:

  1. Idioma: English, Português o Español. Lo usa el panel y es el idioma por defecto del bot. Cada usuario de Telegram puede cambiar el suyo después con /idioma.
  2. Contraseña: al menos 8 caracteres. Protege el panel, y el bot la pide antes de dar acceso a nadie. Que sea larga.
  3. Números de teléfono permitidos: solo las cuentas de Telegram con uno de estos números pueden usar el bot. Incluye el código de país, solo dígitos, con un + inicial opcional (por ejemplo 34612345678). Escribir un número nunca basta: el bot le pide a la persona que comparta su contacto, lo que demuestra que la cuenta es dueña de ese número.
  4. Token del bot de Telegram: opcional. Puedes saltarlo y añadirlo después en Ajustes → Telegram. Consulta la siguiente sección.
04

Crea tu bot de Telegram

Tether necesita un bot propio. Crearlo lleva unos dos minutos y es gratis.

  1. En Telegram, abre @BotFather, el bot oficial para crear bots, y envía /newbot.
  2. Elige un nombre visible, por ejemplo Mi Claude.
  3. Elige un nombre de usuario. Debe terminar en bot, por ejemplo mi_claude_tether_bot.
  4. BotFather responde con un token parecido a 123456789:AAH…. Trátalo como una contraseña.
  5. Pega el token en el asistente o en el panel, en Ajustes → Telegram → Token del bot. El panel lo confirma con “Conectado como @tu_bot”.
  6. Abre tu bot en Telegram y envía /start. Toca 📱 Compartir mi contacto. Tether comprueba que el número está en tu lista de permitidos y que el contacto es realmente tuyo.
  7. Desbloquéalo con /clave tu-contraseña. El bot borra ese mensaje al instante.

Listo. Escribe lo que quieras: tu mensaje va a la sesión activa y la respuesta de Claude vuelve al chat.

Un Tether por token

Telegram solo deja que un programa lea las actualizaciones de un bot a la vez. No uses el mismo token en dos instalaciones de Tether ni en otro framework de bots.

05

Uso del bot

El bot siempre tiene una sesión activa. Todo lo que escribes va allí, con el prefijo [telegram] para que Claude sepa que debe formatear para la pantalla de un teléfono. Cuando Claude termina su turno, te envía la respuesta.

Texto
Se envía a la sesión activa como prompt. Los mensajes largos y de varias líneas no son problema.
Fotos y archivos
Se guardan en tu equipo y se adjuntan al prompt. El pie de foto se convierte en el mensaje. Telegram limita los bots a 20 MB por archivo.
Preguntas
Cuando Claude hace una pregunta, sus opciones aparecen como botones, más ✍️ Otra respuesta para texto libre.
Solicitudes de permiso
En el modo Preguntar, llega “🛡️ sesión quiere usar herramienta” con las mismas opciones que verías en la terminal. Si respondes en el panel o en la terminal, los botones desaparecen y el mensaje indica que se resolvió en otro lugar.
Indicador de escritura
Se muestra mientras la sesión activa está trabajando.

Directorios de trabajo y sesiones

Las sesiones se agrupan por el directorio de trabajo en el que se crearon. Un directorio puede tener varias sesiones de Claude; Tether les pone nombre solo: mi-app, mi-app 2, mi-app 3. Las sesiones creadas antes de que existieran los directorios quedan en la raíz del repositorio git de su carpeta.

/cambiar
Lista tus directorios de trabajo con las sesiones activas/total y el total de mensajes sin leer 📬. Toca uno para ver sus sesiones; si solo tiene una, cambias directamente a ella. /cambiar nombre busca primero el nombre exacto de una sesión y, si no lo encuentra, el de un directorio.
/sesiones
Lista las sesiones del directorio actual. Toca una para cambiar, ➕ Nueva sesión aquí para abrir otro Claude en la misma carpeta, o ⏸️ Pausar todas.

Pausar. /pausar [nombre] pausa una sesión inactiva: su proceso de Claude se detiene para liberar memoria, pero la sesión sigue en la lista (⏸️) y la respuesta trae un botón ▶️ Reanudar. Reanudar continúa la misma conversación, y el estado pausado sobrevive a los reinicios. /pausar todas pausa todas las sesiones inactivas del directorio actual; las ocupadas siguen ejecutándose y aparecen en la respuesta. Para pausar una sesión ocupada, espera a que termine o usa /cancelar antes.

Bloqueo

El bot se bloquea solo tras un tiempo sin uso (12 horas por defecto, configurable en Ajustes → General) y cada vez que Tether se reinicia. Usa /bloquear para bloquearlo ahora. Mientras está bloqueado, el bot no muestra contenido: solo dice “nueva respuesta de X” o “X necesita tu respuesta”. Las respuestas esperan en la bandeja y las solicitudes pendientes se reenvían cuando desbloqueas. Cinco contraseñas incorrectas bloquean a ese usuario durante 15 minutos.

06

07

La bandeja 📬

Las respuestas de otras sesiones no se pierden. Mientras hablas con la sesión A, una respuesta de la sesión B se guarda en tu bandeja y recibes un aviso breve:

✅ B terminó · 📬 1 sin leer — /cambiar B para verla.

Cuando cambias a B, el bot primero te entrega todo lo que llegó mientras no estabas y después pasas a hablar con B. En la lista de /cambiar, 📬 muestra el total sin leer de cada directorio, y /sesiones marca cada sesión con respuestas sin leer. La bandeja se guarda en disco, así que sobrevive a los reinicios.

08

Sesiones nuevas y /reanudar

Abre una sesión en cualquier carpeta: /nueva

/nueva <ruta> [nombre] crea una sesión nueva en cualquier directorio de tu equipo y la convierte en la activa. ~ es tu carpeta personal.

Telegram
/nueva ~/proyectos/mi-app
/nueva ~/trabajo/api backend
/new ~/projects/site
/nova ~/projetos/loja

Si no indicas un nombre, se usa el de la carpeta. La sesión arranca en el modo de permiso por defecto definido en Ajustes → General.

Proyectos recientes: /proyectos

Muestra las carpetas que ya has usado. Toca 💬 nombre para cambiar a una sesión en marcha, o ➕ Nueva para abrir otra sesión allí.

Retoma una conversación antigua: /reanudar

Lista las conversaciones recientes de Claude Code que hay en ~/.claude/projects, incluidas las que empezaste en una terminal normal. Toca una y Tether ejecuta claude --resume en una sesión nueva de tmux, con el modo de permiso por defecto. Una conversación que empezó en un modo puede reanudarse en otro. Si la conversación ya pertenece a una sesión, Tether reinicia esa sesión en lugar de crear una duplicada.

09

El panel

Abre http://127.0.0.1:4100 e inicia sesión con tu contraseña. El inicio de sesión dura 7 días. La barra lateral lista tus sesiones con su estado: Inactiva, Trabajando, Esperando (por ti), Sin conexión o Pausada (gris). Un botón en la parte superior de la barra lateral la colapsa a un carril estrecho de iconos; la preferencia se recuerda entre recargas.

Directorios de trabajo y sesiones

En la barra lateral, las sesiones se agrupan bajo encabezados de directorio plegables: un icono de carpeta, el nombre del directorio y activas/total. Cada grupo tiene Nueva sesión aquí (+), que abre otro Claude en la misma carpeta, y Pausar todas (⏸), que aparece cuando hay algo en marcha; las sesiones ocupadas siguen ejecutándose. El pie de la barra lateral enlaza a este manual, en el idioma del panel, y a GitHub.

Para pausar una sola sesión, usa Pausar en el panel lateral de la sesión, junto a Reiniciar y Quitar. Solo está activo cuando la sesión está inactiva. Una sesión pausada conserva su lugar y su conversación, y muestra Reanudar en vez de Pausar.

Resumen

  • Número de sesiones: total, trabajando, esperándote, sin conexión.
  • Límites de la cuenta (5 horas y 7 días) con la hora de reinicio.
  • Contexto usado por cada sesión.
  • Consumo de las últimas 24 horas, con la línea del límite de 5 horas.
  • Actividad reciente: prompts, llamadas a herramientas, respuestas y solicitudes de permiso.
  • El estado del bot de Telegram, con iniciar, detener y reiniciar.

Chat de la sesión

La conversación completa, leída de la propia transcripción de Claude Code, así que también aparecen los mensajes enviados desde Telegram y los escritos en la terminal, cada uno marcado con su origen. Pulsa Enter para enviar y Shift+Enter para una línea nueva. Las preguntas y las solicitudes de permiso aparecen en el chat con botones.

Adjuntos

Usa el botón de adjuntar o arrastra y suelta archivos en el chat. Se suben a tu equipo y se referencian en el prompt.

Comandos slash

Escribe / en el cuadro de mensaje para abrir el menú de comandos: /model, /effort, /clear, /compact, /usage, /cost o cualquier otro comando que escribas. Usa ↑ ↓ para moverte, Enter para ejecutar y Esc para cerrar.

Modelo y esfuerzo

Los selectores del panel de la sesión cambian el modelo (Opus, Sonnet, Haiku, Fable o Default) y el esfuerzo de razonamiento (de Bajo a Máximo). El panel también muestra el contexto usado, en tokens, y el coste de la sesión.

Terminal

Una vista en vivo y de solo lectura de la ventana de tmux, actualizada cada 1,5 segundos. Útil para las solicitudes que Tether no convierte en botones.

Acciones de la sesión

Renombrar, limpiar el contexto (ejecuta /clear; la conversación anterior queda en su transcripción), reiniciar (detiene y vuelve a arrancar Claude en la misma carpeta), pausar / reanudar (ver arriba) y quitar (Tether deja de gestionar la sesión; también puedes cerrar la sesión de tmux). Las transcripciones en disco nunca se borran.

Nueva sesión (+)

Escribe el directorio de trabajo: las sugerencias vienen de este equipo y Tab completa la ruta. Los proyectos recientes aparecen listados para elegirlos con un clic. También puedes definir un nombre, el modo de permiso y el modelo, y marcar Continuar la última conversación para reanudar la conversación más reciente de esa carpeta (claude -c).

Reanudar (🕘)

Continúa cualquier conversación reciente de Claude Code de este equipo en una sesión nueva. Elige el modo de permiso con el que debe ejecutarse ahora; no importa cómo empezó. Si la conversación ya pertenece a una sesión, se reinicia esa sesión en lugar de duplicarla. El diálogo se puede filtrar por directorio de trabajo para acotar listas largas.

Adoptar (⇄)

Toma el control de una sesión de Claude Code que hayas abierto tú dentro de tmux. Tether lista las sesiones de tmux que todavía no gestiona; indícale cómo se inició ese Claude (con qué modo de permiso) para que sepa si debe esperar solicitudes de permiso.

Ajustes

También: Verificación rápida — ejecuta una serie de comprobaciones (Claude CLI disponible, tmux disponible, Telegram accesible, …) y muestra el resultado de cada una; y Prueba de extremo a extremo — recorre el camino completo desde la creación de la sesión hasta la entrega de la respuesta e informa de cada paso con su duración.

10

Tareas programadas

Las tareas programadas ejecutan un prompt de forma automática según un horario y entregan el resultado a un número de Telegram. Cada ejecución crea una sesión desechable de Claude en modo de permiso bypass; cuando termina (o falla), el resultado se envía al número de notificación y la sesión se elimina.

Crear una tarea programada

En el panel, ve a Programaciones → Nueva tarea y rellena el formulario. En Telegram, envía /programaciones, toca + Nueva y sigue el asistente — te pide cada campo en orden y muestra un resumen antes de guardar.

CampoNotas
NombreAparece en las notificaciones y en el selector de sesión mientras la ejecución está activa.
PromptEl texto que se inyecta en Claude en cada ejecución.
Directorio de trabajoRuta absoluta donde se ejecutará Claude. Debe empezar por /.
FrecuenciaIntervalo: cada N minutos (1–10080). Semanal: días de la semana elegidos a una hora fija HH:MM.
Número de notificaciónUn número de Telegram verificado que recibirá el resultado. Debe estar ya en tu lista de permitidos.
Tiempo límite1–1440 minutos. Si la ejecución supera este tiempo, se cancela y se avisa al número de notificación.
Preservar sesiónCuando está desactivado (por defecto), una ejecución exitosa limpia el contexto (/clear), pausa y elimina la sesión. Cuando está activado, la sesión se conserva al terminar.

Protección contra solapamiento

Si la ejecución anterior de una tarea todavía está en marcha cuando llega el siguiente disparo, el nuevo disparo se registra como omitido y no se crea ninguna sesión nueva. Una tarea nunca se ejecuta dos veces a la vez.

Entre todas las tareas, Ajustes → General → Ejecuciones programadas simultáneas limita cuántas sesiones programadas pueden correr a la vez (predeterminado 2, de 1 a 10). Los disparos que superan el límite también se registran como omitido. El límite se lee en cada ciclo, así que el cambio se aplica sin reiniciar.

Estados de ejecución

EstadoSignificado
runningLa sesión está activa y Claude está trabajando.
waitingClaude ha hecho una pregunta. Se avisa al número de notificación; responder desde Telegram o el panel continúa la ejecución.
successLa ejecución terminó con éxito. El resultado se entregó al número de notificación.
errorLa sesión se desconectó o Claude devolvió un error. Se avisa al número de notificación.
timeoutLa ejecución superó el tiempo límite. Se avisa al número de notificación.
skippedLa ejecución anterior seguía en marcha; este disparo se omitió.
taken_overUn humano escribió en la sesión. El planificador la libera; la sesión pasa a ser tuya para continuar.
discardedLa ejecución fue descartada manualmente desde la cuadrícula de fallos.

Panel: página de Programaciones

  • Tarjetas de estadísticas (ventana de 30 días): total de ejecuciones, exitosas, fallidas, omitidas.
  • Franja de próximas ejecuciones: la hora del próximo disparo para cada tarea activa.
  • Lista de tareas: ejecutar ahora, editar, pausar/reanudar y eliminar para cada tarea.
  • Cuadrícula de fallos: las ejecuciones fallidas se pueden reenviar como nueva ejecución, abrir como sesión activa para terminarlas a mano, o descartar.

Telegram: comandos de programación

/programaciones (alias /schedules, /agendamentos) lista todas las tareas programadas. ▶️ significa activa, ⏸️ significa pausada. Toca una tarea para ver sus últimas cinco ejecuciones y obtener botones de Ejecutar ahora, Pausar / Activar y Eliminar. Toca + Nueva para iniciar el asistente de creación.

Las sesiones de tareas programadas en ejecución aparecen en el selector de sesión (/cambiar, /sesiones) para que puedas acceder a ellas en cualquier momento. Si escribes en una, la ejecución se marca como taken_over y la sesión se convierte en una sesión interactiva normal.

Cuenta bloqueada

Si el bot está bloqueado cuando termina una ejecución programada, la notificación avisa de que la tarea se completó y pide que desbloquees antes de entregar el informe completo. Desbloquea con /clave como de costumbre.

11

Modos de permiso

Cada sesión se ejecuta en uno de tres modos, que eliges al crearla, reanudarla o adoptarla. El modo por defecto se define en Ajustes → General.

ModoComportamiento
Preguntar (Ask)Cada solicitud de permiso llega a Telegram y al panel con botones. Responde desde donde quieras; los demás sitios se actualizan.
Auto recomendadoClaude trabaja por su cuenta. El clasificador de seguridad integrado en Claude Code revisa cada acción y bloquea las arriesgadas, incluidas las provocadas por inyección de prompts (instrucciones ocultas en archivos, páginas web o issues).
Omitir (Bypass)Claude se ejecuta con --dangerously-skip-permissions y nunca pregunta. Nadie revisa sus acciones.

El modo se aplica al arrancar la sesión. Para cambiarlo, reanuda la conversación en el otro modo: una conversación que empezó en un modo puede continuar en otro.

Sobre Omitir

Claude editará archivos y ejecutará comandos en tu equipo sin preguntar. Úsalo solo en carpetas de confianza, con trabajo que puedas deshacer, y nunca con contenido que no hayas escrito tú.

Cada solicitud de permiso lleva un identificador derivado de lo que se mostró, y la pantalla se vuelve a leer justo antes de enviar una respuesta. Un botón antiguo no puede aprobar una solicitud más nueva; se rechaza con “ya no está pendiente”.

12

Seguridad

Quien controle Tether puede hacer que Claude ejecute comandos con tu usuario. El diseño parte de esa premisa y pone varias barreras delante.

CapaProtección
Identidad en TelegramCada usuario debe compartir su propio contacto, y el número debe estar en la lista de permitidos. Los demás no reciben nada más que la petición de “compartir contacto”.
ContraseñaSe pide tras cada reinicio y tras el tiempo de inactividad. El mensaje de /clave se borra. 5 intentos fallidos bloquean al usuario durante 15 minutos. Mientras está bloqueado, el bot no muestra contenido.
Configuración obligatoriaEl bot no arranca sin contraseña y sin al menos un número permitido. El último número no se puede eliminar.
Acceso al panelLa misma contraseña. Cookie HttpOnly y SameSite=Strict; solo se guarda un hash del token. 5 intentos fallidos bloquean la dirección durante 15 minutos. Cambiar la contraseña cierra todas las demás sesiones y bloquea el bot.
RedEscucha en 127.0.0.1. La cabecera Host debe nombrar a este servidor (sin DNS rebinding); las peticiones que cambian el estado necesitan un Origin permitido y un cuerpo JSON, así que los formularios entre sitios se rechazan.
HooksLos endpoints de los hooks exigen un token aleatorio, leído de un archivo para que nunca aparezca en la lista de procesos.
Secretos en reposoContraseña con hash scrypt; token del bot cifrado con AES-256-GCM usando una clave local. ~/.tether tiene modo 700 y sus archivos, 600.
Alcance de Claudetether setup añade reglas de denegación de Claude Code para que las herramientas de archivos de Claude no puedan leer ni editar ~/.tether (token del bot, hash de la contraseña, clave) ni ~/.ssh. Para los comandos de terminal también, activa el sandbox de Claude Code (/sandbox); sin él, la barrera es el clasificador del modo Auto.
Ejecución de procesosNunca se construyen cadenas de shell a partir de la entrada. tmux y claude se llaman con listas de argumentos y valores validados; los prompts se pegan mediante un archivo de búfer privado de tmux.
Registro de auditoríaSe registran los inicios de sesión, los desbloqueos, los cambios de token, contraseña y lista de permitidos, las acciones sobre sesiones y las respuestas a permisos.

Recomendaciones

  • Activa la verificación en dos pasos de Telegram (Telegram → Ajustes → Privacidad y seguridad → Verificación en dos pasos). La lista de permitidos confía en tu cuenta de Telegram, así que protégela contra el duplicado de SIM y el robo de códigos de acceso.
  • Usa Auto o Preguntar con contenido que no sea de confianza. Los repositorios clonados, las páginas web, las issues y los documentos pueden contener inyección de prompts. Reserva Omitir para tu propio código, en carpetas donde no te importe que Claude actúe sin supervisión.
  • Nunca expongas el puerto 4100 a internet. Para acceder al panel en remoto, usa una VPN o un proxy inverso con autenticación, y ajusta TETHER_HOST en consecuencia.
  • Usa una contraseña larga. Cualquiera que encuentre el nombre de usuario de tu bot puede escribirle; la lista de permitidos y la contraseña son lo que lo detiene.
  • Renueva el token del bot en @BotFather (/revoke) si alguna vez crees que se ha filtrado, y pega el nuevo en Ajustes → Telegram.
  • Completa el asistente justo después de instalar y mantén las reglas de denegación de tether setup.

Tether no intenta defenderse del software que ya se ejecuta con tu usuario o como root: ese software puede leer ~/.tether y controlar tmux directamente. Consulta SECURITY.md para ver el modelo completo y cómo informar de una vulnerabilidad.

Solución de problemas

Empieza por tether doctor. Comprueba los problemas más comunes.

El bot no responde nada
Solo responde a números permitidos. Envía /start y comparte tu contacto. Si aun así te ignora, revisa el número en Ajustes → Seguridad (dígitos con código de país) y el registro del servidor.
“Conflict: terminated by other getUpdates request”
Dos programas usan el mismo token de bot. Detén el otro: solo un Tether por token.
Las sesiones muestran “modelo desconocido” o ningún % de contexto
El reenviador de la línea de estado aún no está activo en esa sesión. Ejecuta tether setup y reinicia la sesión.
Después de reiniciar el equipo, todas las sesiones están sin conexión
Las sesiones de tmux no sobreviven al reinicio. Envía /cambiar, elige la sesión y toca 🔄 Reiniciar sesión: continúa la misma conversación. Reiniciar en el panel hace lo mismo.
Una sesión que abrí yo no aparece en la lista
Ábrela dentro de tmux y usa Adoptar en el panel. O usa Reanudar para reabrir su conversación.
Las respuestas no llegan después de /clear
Deberían llegar. Si no, comprueba que los hooks están instalados con tether doctor.
Claude hace varias preguntas a la vez
Solo la primera pregunta, o la primera de una selección múltiple, recibe botones. Responde al resto en la vista de terminal del panel, o con /pantalla y una respuesta de texto libre.
No puedo entrar en el panel
Tras 5 intentos fallidos, la dirección se bloquea durante 15 minutos. En localhost todos los clientes comparten 127.0.0.1, así que espera o restablece la contraseña con tether passwd.
Olvidé la contraseña
Ejecuta tether passwd en el equipo.
¿Dónde están los registros?
journalctl --user -u telegram-claude-tether -f para el servicio, o la terminal donde se ejecuta tether. Define TETHER_DEBUG=1 para ver más detalles.

Contribuir y traducir

Las issues y los pull requests son bienvenidos. Los pull requests pequeños y enfocados son los más fáciles de revisar.

Desarrollo
$ npm install
$ npm run dev        # servidor en :4100 (recarga), panel en :5173
$ npm test           # pruebas unitarias
$ npm run typecheck  # servidor + panel

Para mantener una instancia de desarrollo separada de una instalación real, ejecuta TETHER_HOME=/tmp/tether-dev TETHER_PORT=4200 npm run dev:server.

  • Primero el contrato: si cambia un endpoint o un mensaje, actualiza src/shared/api.ts y ambos lados en el mismo PR.
  • Nunca construyas cadenas de shell a partir de la entrada del usuario. Usa execFile con arrays de argumentos.
  • Los cambios sensibles para la seguridad deben explicar su modelo de amenazas en la descripción del PR.
  • Añade una prueba para cualquier lógica de parsing o de seguridad.

Añadir un idioma

  1. Copia locales/en/ a locales/<código>/ (p. ej. fr, de, zh-CN).
  2. Traduce bot.json y web.json. Conserva los {{placeholders}} y las etiquetas HTML.
  3. Añade el código a SUPPORTED_LOCALES en src/server/settings.ts, a la lista de idiomas de web/src/lib/i18n.ts y a las etiquetas de /lang del bot.
  4. Opcionalmente, añade alias de comandos traducidos en src/server/bot/bot.ts. Los comandos de Telegram solo pueden usar a–z, 0–9 y _.

Ejecuta npm test: una prueba comprueba que cada idioma tiene las mismas claves que el inglés. Consulta CONTRIBUTING.md y ARCHITECTURE.md para más detalles.
