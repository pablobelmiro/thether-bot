01

Requirements

Tether runs on the same computer as Claude Code. That machine needs:

  • Linux or macOS. Windows isn't supported.
  • Node.js 22.13 or newer. With nvm: nvm install 22.
  • tmux and curl. apt install tmux or brew install tmux.
  • Claude Code, installed and logged in. Run claude once in a terminal to make sure it works.
  • A Telegram account, if you want to use the bot. The dashboard works without it.

You don't need an API key. Tether uses your local claude login.

02

Installation

Terminal
$ git clone https://github.com/pablobelmiro/thether-bot.git
$ cd thether-bot
$ ./install.sh

The installer:

  1. checks the requirements (OS, Node version, tmux, curl, claude);
  2. installs the dependencies and builds the project;
  3. links the tether command into ~/.local/bin;
  4. runs tether setup: adds Tether's hooks and status line forwarder to ~/.claude/settings.json (keeping a backup), adds deny rules that protect your secrets, and appends one line to ~/.claude/CLAUDE.md so Claude formats answers well for Telegram;
  5. on Linux, offers to run Tether as a systemd user service that starts automatically and restarts on failure.

Installer flags

FlagEffect
(none)Interactive: asks before installing the hooks and the service.
--yes, -yAccept every default (hooks and service) without asking.
--no-hooksDon't touch ~/.claude. Run tether setup later: without the hooks, Tether can't see your sessions.
--no-serviceDon't offer the systemd service. Start Tether yourself with tether.
-h, --helpShow the usage.
PATH

If the installer warns that ~/.local/bin isn't in your PATH, add export PATH="$HOME/.local/bin:$PATH" to your shell profile and open a new terminal.

If you installed the service, Tether is already running. Otherwise start it with tether and keep that terminal open. Then open http://127.0.0.1:4100 in a browser on the same machine.

03

First-run wizard

Do this right away

Until a password is set, the setup page is open to anything that can reach 127.0.0.1:4100. Finish the wizard right after installing. On a shared machine, stop the service until you do.

The first time you open the dashboard, a short wizard asks for four things:

  1. Language: English, Português or Español. It's used by the dashboard and as the default for the bot. Each Telegram user can change theirs later with /lang.
  2. Password: at least 8 characters. It protects the dashboard, and the bot asks for it before giving anyone access. Make it long.
  3. Allowed phone numbers: only Telegram accounts with one of these numbers can use the bot. Include the country code, digits only, with an optional leading + (for example 5511999998888). Typing a number is never enough: the bot asks the person to share their contact, which proves the account owns that number.
  4. Telegram bot token: optional. You can skip it and add it later in Settings → Telegram. See the next section.
04

Create your Telegram bot

Tether needs a bot of your own. Creating one takes about two minutes and is free.

  1. In Telegram, open @BotFather, the official bot for creating bots, and send /newbot.
  2. Choose a display name, for example My Claude.
  3. Choose a username. It must end in bot, for example my_claude_tether_bot.
  4. BotFather replies with a token that looks like 123456789:AAH…. Treat it like a password.
  5. Paste the token in the wizard, or in the dashboard under Settings → Telegram → Bot token. The dashboard confirms with “Connected as @your_bot”.
  6. Open your bot in Telegram and send /start. Tap 📱 Share my contact. Tether checks that the number is on your allow list and that the contact is really yours.
  7. Unlock with /password your-password. The bot deletes that message right away.

That's it. Type anything: your message goes to the active session, and Claude's answer comes back to the chat.

One Tether per token

Telegram lets only one program read a bot's updates at a time. Don't use the same token in two Tether installs, or in another bot framework.

05

Using the bot

The bot always has one active session. Anything you type goes there, prefixed with [telegram] so Claude knows to format for a phone screen. When Claude finishes its turn, the answer is sent back to you.

Text
Sent to the active session as a prompt. Long and multi-line messages are fine.
Photos and files
Saved on your machine and attached to the prompt. The caption becomes the message. Telegram limits bots to 20 MB per file.
Questions
When Claude asks a question, its options appear as buttons, plus ✍️ Other answer for free text.
Permission prompts
In Ask mode, “🛡️ session wants to use tool” arrives with the same options you'd see in the terminal. If you answer in the dashboard or the terminal instead, the buttons are removed and the message says it was resolved elsewhere.
Typing indicator
Shown while the active session is working.

Locking

The bot locks itself after a period without use (12 hours by default, configurable in Settings → General) and every time Tether restarts. Use /lock to lock it now. While it's locked, the bot shows no content: it only says “new answer from X” or “X needs your answer”. Answers wait in the inbox, and pending prompts are sent again after you unlock. Five wrong passwords block that user for 15 minutes.

Every command has an English name. Localized aliases work in any language, and the bot's menu shows the names for your language.

07

The 📬 inbox

Answers from other sessions don't get lost. While you're talking to session A, an answer from session B is kept in your inbox, and you get a short notice:

✅ B finished · 📬 1 unread — /change B to read it.

When you switch to B, the bot first delivers everything that arrived while you were away, then you're talking to B. In the /change list, 📬 marks the sessions that have unread answers. The inbox is stored on disk, so it survives restarts.

08

New sessions and /resume

Start a session in any folder: /new

/new <path> [name] creates a new session in any directory on your machine and makes it active. ~ means your home folder.

Telegram
/new ~/projects/my-app
/new ~/work/api backend
/nova ~/projetos/site
/nueva ~/proyectos/tienda

The optional name defaults to the folder name. The session starts in the default permission mode set in Settings → General.

Recent projects: /repos

Shows the folders you've used before. Tap 💬 name to switch to a running session, or ➕ New to open another session there.

Pick up an old conversation: /resume

Lists recent Claude Code conversations found in ~/.claude/projects, including ones started in a plain terminal. Tap one and Tether runs claude --resume in a new tmux session, in the default permission mode. A conversation that began in one mode can be resumed in another.

09

The dashboard

Open http://127.0.0.1:4100 and sign in with your password. The login lasts 7 days. The sidebar lists your sessions with their state: Idle, Working, Waiting (for you) or Offline.

Overview

  • Session counts: total, working, waiting for you, offline.
  • Account limits (5-hour and 7-day) with reset times.
  • Context used by each session.
  • Usage over the last 24 hours, with the 5-hour limit line.
  • Recent activity: prompts, tool calls, responses and permission requests.
  • The Telegram bot's state, with start, stop and restart.

Session chat

The full conversation, read from Claude Code's own transcript, so messages sent from Telegram and typed in the terminal show up too, each marked with where it came from. Press Enter to send and Shift+Enter for a new line. Questions and permission prompts appear in the chat with buttons.

Attachments

Use the attach button or drag and drop files onto the chat. They're uploaded to your machine and referenced in the prompt.

Slash commands

Type / in the message box to open the command menu: /model, /effort, /clear, /compact, /usage, /cost, or any other command you type. Use ↑ ↓ to move, Enter to run and Esc to close.

Model and effort

Selectors in the session panel change the model (Opus, Sonnet, Haiku, Fable or Default) and the reasoning effort (Low to Max). The panel also shows the context used, in tokens, and the session's cost.

Terminal

A read-only live view of the tmux pane, refreshed every 1.5 seconds. Useful for prompts Tether doesn't turn into buttons.

Session actions

Rename, clear context (runs /clear; the old conversation stays in its transcript), restart (stops and starts Claude in the same folder) and remove (Tether stops managing the session; you can also kill the tmux session). Transcripts on disk are never deleted.

New session (+)

Type the working directory: suggestions come from this machine, and Tab completes the path. Recent projects are listed for one-click picking. You can also set a name, the permission mode and the model, and choose Continue last conversation to resume the most recent conversation in that folder (claude -c).

Resume (🕘)

Continue any recent Claude Code conversation from this machine in a new session. Choose the permission mode it should run with now; how it was started doesn't matter.

Adopt (⇄)

Take over a Claude Code session you started yourself inside tmux. Tether lists the tmux sessions it doesn't manage yet; tell it how that Claude was started (which permission mode) so it knows whether to expect permission prompts.

Settings

TabWhat's there
GeneralLanguage, default permission mode for new and adopted sessions, idle lock (hours before the bot asks for the password again).
TelegramTurn the bot on or off, paste or replace the token, see verified users and revoke their access.
SecurityChange the password; add or remove allowed phone numbers, with an optional label.
Audit logSecurity-relevant actions, newest first: who did what, from where.
10

Permission modes

Each session runs in one of three modes, chosen when you create, resume or adopt it. The default is set in Settings → General.

ModeBehavior
AskEvery permission prompt goes to Telegram and the dashboard with buttons. Answer from anywhere; the other places update.
Auto recommendedClaude works on its own. Claude Code's built-in safety classifier reviews each action and blocks risky ones, including actions pushed by prompt injection (instructions hidden in files, web pages or issues).
BypassClaude runs with --dangerously-skip-permissions and never asks. Nothing reviews its actions.

The mode applies when the session starts. To change it, resume the conversation in the other mode: a conversation that began in one mode can continue in another.

About Bypass

Claude will edit files and run commands on your machine without asking. Use it only in folders you trust, with work you can undo, and never on content you didn't write yourself.

Each permission prompt carries an id derived from what was shown, and the screen is re-read right before an answer is sent. A stale button can't approve a newer prompt; it's refused with “no longer pending”.

11

Security

Anyone who controls Tether can make Claude run commands as your user. The design assumes that and puts several barriers in front of it.

LayerProtection
Telegram identityUsers must share their own contact, and the number must be on the allow list. Everyone else gets no answer beyond the “share contact” prompt.
PasswordRequired after every restart and after the idle timeout. The /password message is deleted. 5 wrong attempts block the user for 15 minutes. While locked, the bot shows no content.
Mandatory setupThe bot won't start without a password and at least one allowed number. The last number can't be removed.
Dashboard loginSame password. HttpOnly, SameSite=Strict cookie; only a hash of the token is stored. 5 failed logins block the address for 15 minutes. Changing the password logs out every other session and locks the bot.
NetworkBinds to 127.0.0.1. The Host header must name this server (no DNS rebinding); state-changing requests need an allowed Origin and a JSON body, so cross-site forms are rejected.
HooksHook endpoints require a random token, read from a file so it never appears in the process list.
Secrets at restPassword hashed with scrypt; bot token encrypted with AES-256-GCM using a local key. ~/.tether is mode 700 and its files 600.
Claude's reachtether setup adds Claude Code deny rules so Claude can't read or edit ~/.tether (bot token, password hash, key) or ~/.ssh.
Process executionNo shell strings are built from input. tmux and claude are called with argument lists and validated values; prompts are pasted through a private tmux buffer file.
Audit logLogins, unlocks, token / password / allow-list changes, session actions and permission answers are recorded.

Recommendations

  • Turn on Telegram two-step verification (Telegram → Settings → Privacy and Security → Two-Step Verification). The allow list trusts your Telegram account, so protect the account from SIM swaps and stolen login codes.
  • Use Auto or Ask for untrusted content. Cloned repositories, web pages, issues and documents can contain prompt injection. Keep Bypass for your own code in folders where you'd be fine with Claude acting unattended.
  • Never expose port 4100 to the internet. For remote access to the dashboard, use a VPN or an authenticated reverse proxy, and set TETHER_HOST accordingly.
  • Use a long password. Anyone who finds your bot's username can message it; the allow list and the password are what stop them.
  • Rotate the bot token in @BotFather (/revoke) if you ever think it leaked, then paste the new one in Settings → Telegram.
  • Finish the wizard right after installing, and keep tether setup's deny rules in place.

Tether doesn't try to defend against software already running as your user or as root: it can read ~/.tether and control tmux directly. See SECURITY.md for the full model and how to report a vulnerability.

12

Configuration

Everything user-facing lives in the dashboard and is stored in ~/.tether/tether.db. Process options are environment variables:

VariableDefaultMeaning
TETHER_PORT4100HTTP port.
TETHER_HOST127.0.0.1Bind address. Keep it local.
TETHER_HOME~/.tetherDatabase, keys and uploads.
TETHER_CLAUDE_BINclaudeClaude Code executable.
CLAUDE_CONFIG_DIR~/.claudeClaude Code settings and transcripts.
TETHER_DEBUG1 for verbose logs.
TETHER_DEV_ORIGINSExtra browser origins allowed to call the API, comma-separated. Development only.

Seeding settings from a file

tether import-env <file> reads KEY=VALUE lines, which is handy for scripted installs. Delete the file afterwards.

tether.env
TETHER_PASSWORD=change-me-to-something-long
# Comma-separated, with country code
TETHER_PHONES=15551234567
# From @BotFather
TETHER_TELEGRAM_TOKEN=
# en | pt-BR | es
TETHER_LOCALE=en
# ask | auto | bypass
TETHER_PERMISSION_MODE=auto

14

Troubleshooting

Start with tether doctor. It checks the most common problems.

The bot doesn't answer at all
It only answers allowed numbers. Send /start and share your contact. If it still ignores you, check the number in Settings → Security (digits with country code) and the server log.
“Conflict: terminated by other getUpdates request”
Two programs are using the same bot token. Stop the other one: only one Tether per token.
Sessions show “unknown model” or no context %
The status line forwarder isn't active for that session yet. Run tether setup, then restart the session.
A session I started myself isn't listed
Start it inside tmux, then use Adopt in the dashboard. Or use Resume to reopen its conversation.
Answers don't arrive after /clear
They should. If not, check that the hooks are installed with tether doctor.
Claude asks several questions at once
Only the first question, or the first of a multi-select, gets buttons. Answer the rest in the dashboard terminal view, or with /screen and a free-text reply.
I'm locked out of the dashboard
After 5 failed logins the address is blocked for 15 minutes. On localhost every client shares 127.0.0.1, so wait, or reset the password with tether passwd.
Forgot the password
Run tether passwd on the machine.
Where are the logs?
journalctl --user -u telegram-claude-tether -f for the service, or the terminal running tether. Set TETHER_DEBUG=1 for more detail.
15

Uninstall

Terminal
$ tether service uninstall      # if you installed the service
$ tether uninstall-hooks
$ rm -rf ~/.tether ~/.local/bin/tether

Then delete the cloned folder. Your Claude Code transcripts in ~/.claude/projects are not touched. You can also delete the bot in @BotFather with /deletebot.

16

Contributing & translations

Issues and pull requests are welcome. Small, focused pull requests are easiest to review.

Development
$ npm install
$ npm run dev        # server on :4100 (reloads), dashboard on :5173
$ npm test           # unit tests
$ npm run typecheck  # server + dashboard

To keep a development instance apart from a real install, run TETHER_HOME=/tmp/tether-dev TETHER_PORT=4200 npm run dev:server.

  • The contract first: if an endpoint or message changes, update src/shared/api.ts and both sides in the same PR.
  • Never build shell strings from user input. Use execFile with argument arrays.
  • Security-sensitive changes should explain their threat model in the PR description.
  • Add a test for any parsing or security logic.

Adding a language

  1. Copy locales/en/ to locales/<code>/ (e.g. fr, de, zh-CN).
  2. Translate bot.json and web.json. Keep the {{placeholders}} and the HTML tags.
  3. Add the code to SUPPORTED_LOCALES in src/server/settings.ts, to the language list in web/src/lib/i18n.ts and to the bot's /lang labels.
  4. Optionally add localized command aliases in src/server/bot/bot.ts. Telegram commands may only use a–z, 0–9 and _.

Run npm test: a test checks that every locale has the same keys as English. See CONTRIBUTING.md and ARCHITECTURE.md for more.
