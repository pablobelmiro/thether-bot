01

Requisitos

O Tether roda no mesmo computador que o Claude Code. Essa máquina precisa de:

  • Linux ou macOS. O Windows não é suportado.
  • Node.js 22.13 ou mais recente. Com o nvm: nvm install 22.
  • tmux e curl. apt install tmux ou brew install tmux.
  • Claude Code, instalado e com login feito. Rode claude uma vez no terminal para conferir se funciona.
  • Uma conta do Telegram, se você quiser usar o bot. O painel funciona sem ela.

Você não precisa de chave de API. O Tether usa o seu login local do claude.

02

Instalação

Terminal
$ git clone https://github.com/pablobelmiro/thether-bot.git
$ cd thether-bot
$ ./install.sh

O instalador:

  1. verifica os requisitos (sistema, versão do Node, tmux, curl, claude);
  2. instala as dependências e compila o projeto;
  3. cria o link do comando tether em ~/.local/bin;
  4. roda o tether setup: adiciona os hooks do Tether e o repassador da linha de status ao ~/.claude/settings.json (guardando um backup), adiciona regras de bloqueio que protegem os seus segredos e acrescenta uma linha ao ~/.claude/CLAUDE.md para que o Claude formate bem as respostas para o Telegram;
  5. no Linux, oferece rodar o Tether como um serviço de usuário do systemd, que inicia sozinho e reinicia em caso de falha. Reiniciar ou parar o serviço não derruba as sessões do Claude que estão rodando.

Opções do instalador

OpçãoEfeito
(nenhuma)Interativo: pergunta antes de instalar os hooks e o serviço.
--yes, -yAceita todos os padrões (hooks e serviço) sem perguntar.
--no-hooksNão mexe no ~/.claude. Rode tether setup depois: sem os hooks, o Tether não enxerga as suas sessões.
--no-serviceNão oferece o serviço do systemd. Inicie o Tether você mesmo com tether.
-h, --helpMostra o modo de uso.
PATH

Se o instalador avisar que ~/.local/bin não está no seu PATH, adicione export PATH="$HOME/.local/bin:$PATH" ao perfil do seu shell e abra um novo terminal.

Se você instalou o serviço, o Tether já está rodando. Caso contrário, inicie-o com tether e deixe esse terminal aberto. Depois abra http://127.0.0.1:4100 num navegador da mesma máquina.

03

Assistente de primeira execução

Faça isto logo

Enquanto não houver senha definida, a página de configuração fica aberta para qualquer coisa que alcance 127.0.0.1:4100. Conclua o assistente logo depois de instalar. Numa máquina compartilhada, pare o serviço até terminar.

Na primeira vez que você abre o painel, um assistente curto pede quatro coisas:

  1. Idioma: English, Português ou Español. É usado pelo painel e como padrão do bot. Cada usuário do Telegram pode trocar o seu depois com /idioma.
  2. Senha: no mínimo 8 caracteres. Ela protege o painel, e o bot a pede antes de dar acesso a qualquer pessoa. Use uma senha longa.
  3. Telefones autorizados: só contas do Telegram com um desses números podem usar o bot. Inclua o código do país, apenas dígitos, com um + opcional no início (por exemplo 5511999998888). Digitar um número nunca basta: o bot pede que a pessoa compartilhe o contato, o que prova que a conta é dona daquele número.
  4. Token do bot do Telegram: opcional. Você pode pular e adicioná-lo depois em Configurações → Telegram. Veja a próxima seção.
04

Crie o seu bot do Telegram

O Tether precisa de um bot só seu. Criar um leva uns dois minutos e é de graça.

  1. No Telegram, abra o @BotFather, o bot oficial para criar bots, e envie /newbot.
  2. Escolha um nome de exibição, por exemplo Meu Claude.
  3. Escolha um nome de usuário. Ele precisa terminar em bot, por exemplo meu_claude_tether_bot.
  4. O BotFather responde com um token parecido com 123456789:AAH…. Trate-o como uma senha.
  5. Cole o token no assistente, ou no painel em Configurações → Telegram → Token do bot. O painel confirma com “Conectado como @seu_bot”.
  6. Abra o seu bot no Telegram e envie /start. Toque em 📱 Compartilhar meu contato. O Tether confere se o número está na sua lista de autorizados e se o contato é mesmo seu.
  7. Desbloqueie com /senha sua-senha. O bot apaga essa mensagem na hora.

Pronto. Digite qualquer coisa: a mensagem vai para a sessão ativa, e a resposta do Claude volta para o chat.

Um Tether por token

O Telegram só deixa um programa por vez ler as atualizações de um bot. Não use o mesmo token em duas instalações do Tether nem em outro framework de bots.

05

Usando o bot

O bot sempre tem uma sessão ativa. Tudo o que você digita vai para ela, com o prefixo [telegram], para que o Claude saiba formatar para a tela do celular. Quando o Claude termina o turno, a resposta é enviada de volta para você.

Texto
Enviado à sessão ativa como prompt. Mensagens longas e com várias linhas não têm problema.
Fotos e arquivos
Salvos na sua máquina e anexados ao prompt. A legenda vira a mensagem. O Telegram limita os bots a 20 MB por arquivo.
Perguntas
Quando o Claude faz uma pergunta, as opções aparecem como botões, além de ✍️ Outra resposta para texto livre.
Pedidos de permissão
No modo Perguntar, “🛡️ sessão quer usar ferramenta” chega com as mesmas opções que você veria no terminal. Se você responder pelo painel ou pelo terminal, os botões somem e a mensagem informa que foi resolvido em outro lugar.
Indicador de digitação
Aparece enquanto a sessão ativa está trabalhando.

Diretórios de trabalho e sessões

As sessões são agrupadas pelo diretório de trabalho em que foram criadas. Um diretório pode ter várias sessões do Claude; o Tether dá os nomes sozinho: meu-app, meu-app 2, meu-app 3. Sessões criadas antes dos diretórios existirem ficam na raiz do repositório git da pasta delas.

/trocar
Lista os seus diretórios de trabalho com as sessões rodando/total e o total de não lidas 📬. Toque em um para ver as sessões dele; se ele tiver só uma, você troca direto para ela. /trocar nome procura primeiro o nome exato de uma sessão e, se não achar, o nome de um diretório.
/sessoes
Lista as sessões do diretório atual. Toque em uma para trocar, em ➕ Nova sessão aqui para abrir outro Claude na mesma pasta, ou em ⏸️ Pausar todas.

Pausar. /pausar [nome] pausa uma sessão ociosa: o processo do Claude é encerrado para liberar memória, mas a sessão continua na lista (⏸️) e a resposta traz um botão ▶️ Retomar. Retomar continua a mesma conversa, e o estado pausado sobrevive a reinícios. /pausar todas pausa todas as sessões ociosas do diretório atual; as ocupadas continuam rodando e aparecem na resposta. Para pausar uma sessão ocupada, espere ela terminar ou use /cancelar antes.

Bloqueio

O bot se trava sozinho depois de um período sem uso (12 horas por padrão, configurável em Configurações → Geral) e sempre que o Tether reinicia. Use /travar para travá-lo na hora. Enquanto está travado, o bot não mostra conteúdo: só avisa “nova resposta de X” ou “X precisa da sua resposta”. As respostas esperam na caixa de entrada, e os pedidos pendentes são reenviados depois do desbloqueio. Cinco senhas erradas bloqueiam aquele usuário por 15 minutos.

07

A caixa de entrada 📬

As respostas das outras sessões não se perdem. Enquanto você conversa com a sessão A, uma resposta da sessão B fica guardada na sua caixa de entrada, e você recebe um aviso curto:

✅ B terminou · 📬 1 não lida — /trocar B para ver.

Quando você troca para B, o bot primeiro entrega tudo o que chegou enquanto você estava fora e, em seguida, você passa a conversar com B. Na lista do /trocar, 📬 mostra o total de não lidas de cada diretório, e o /sessoes marca cada sessão com respostas não lidas. A caixa de entrada fica salva em disco, então sobrevive a reinícios.

08

Novas sessões e /retomar

Abra uma sessão em qualquer pasta: /nova

/nova <caminho> [nome] (ou /new) cria uma nova sessão em qualquer diretório da sua máquina e a torna ativa. ~ é a sua pasta pessoal.

Telegram
/nova ~/projetos/meu-app
/nova ~/trabalho/api backend
/new ~/projects/my-app
/nueva ~/proyectos/tienda

O nome é opcional e, por padrão, é o nome da pasta. A sessão começa no modo de permissão padrão definido em Configurações → Geral.

Projetos recentes: /repos

Mostra as pastas que você já usou. Toque em 💬 nome para ir para uma sessão em andamento, ou em ➕ Nova para abrir outra sessão ali.

Continue uma conversa antiga: /retomar

Lista as conversas recentes do Claude Code encontradas em ~/.claude/projects, inclusive as iniciadas num terminal comum. Toque em uma e o Tether roda claude --resume numa nova sessão do tmux, no modo de permissão padrão. Uma conversa que começou num modo pode ser retomada em outro. Se a conversa já pertence a uma sessão, o Tether reinicia essa sessão em vez de criar uma duplicada.

09

O painel

Abra http://127.0.0.1:4100 e entre com a sua senha. O login dura 7 dias. A barra lateral lista as suas sessões com o estado de cada uma: Ociosa, Trabalhando, Aguardando (você), Offline ou Pausada (cinza). Um botão no topo da barra lateral recolhe-a para uma faixa estreita de ícones; a escolha é lembrada entre recarregamentos.

Diretórios de trabalho e sessões

Na barra lateral, as sessões ficam agrupadas sob cabeçalhos de diretório recolhíveis: um ícone de pasta, o nome do diretório e rodando/total. Cada grupo tem Nova sessão aqui (+), que abre outro Claude na mesma pasta, e Pausar todas (⏸), que aparece quando algo ali está rodando; as sessões ocupadas continuam rodando. O rodapé da barra lateral tem links para este manual, no idioma do painel, e para o GitHub.

Para pausar uma sessão, use Pausar no painel lateral da sessão, ao lado de Reiniciar e Remover. O botão só fica ativo quando a sessão está ociosa. Uma sessão pausada mantém o lugar e a conversa, e mostra Retomar em vez de Pausar.

Visão geral

  • Contagem de sessões: total, trabalhando, aguardando você, offline.
  • Limites da conta (5 horas e 7 dias) com horário de renovação.
  • Contexto usado por cada sessão.
  • Uso nas últimas 24 horas, com a linha do limite de 5 horas.
  • Atividade recente: prompts, chamadas de ferramentas, respostas e pedidos de permissão.
  • O estado do bot do Telegram, com iniciar, parar e reiniciar.

Chat da sessão

A conversa completa, lida da própria transcrição do Claude Code; por isso as mensagens enviadas pelo Telegram e digitadas no terminal também aparecem, cada uma marcada com a origem. Enter envia e Shift+Enter quebra a linha. Perguntas e pedidos de permissão aparecem no chat com botões.

Anexos

Use o botão de anexar ou arraste arquivos para o chat. Eles são enviados para a sua máquina e referenciados no prompt.

Comandos de barra

Digite / na caixa de mensagem para abrir o menu de comandos: /model, /effort, /clear, /compact, /usage, /cost ou qualquer outro comando que você digitar. Use ↑ ↓ para navegar, Enter para executar e Esc para fechar.

Modelo e esforço

Seletores no painel da sessão trocam o modelo (Opus, Sonnet, Haiku, Fable ou Padrão) e o esforço de raciocínio (de Baixo a Máximo). O painel também mostra o contexto usado, em tokens, e o custo da sessão.

Terminal

Uma visualização ao vivo, somente leitura, da janela do tmux, atualizada a cada 1,5 segundo. Útil para telas que o Tether não transforma em botões.

Ações da sessão

Renomear, limpar contexto (roda /clear; a conversa anterior continua na transcrição), reiniciar (para e inicia o Claude de novo na mesma pasta), pausar / retomar (veja acima) e remover (o Tether deixa de gerenciar a sessão; você também pode encerrar a sessão do tmux). As transcrições em disco nunca são apagadas.

Nova sessão (+)

Digite o diretório de trabalho: as sugestões vêm desta máquina, e Tab completa o caminho. Os projetos recentes aparecem listados para escolher com um clique. Também dá para definir um nome, o modo de permissão e o modelo, e marcar Continuar a última conversa para retomar a conversa mais recente daquela pasta (claude -c).

Retomar (🕘)

Continue qualquer conversa recente do Claude Code desta máquina numa nova sessão. Escolha o modo de permissão com que ela deve rodar agora; não importa como ela foi iniciada. Se a conversa já pertence a uma sessão, essa sessão é reiniciada em vez de duplicada. A janela pode ser filtrada por diretório de trabalho para facilitar a busca em listas longas.

Adotar (⇄)

Assuma uma sessão do Claude Code que você mesmo iniciou dentro do tmux. O Tether lista as sessões do tmux que ele ainda não gerencia; informe como aquele Claude foi iniciado (em qual modo de permissão) para ele saber se deve esperar pedidos de permissão.

Configurações

AbaO que tem lá
GeralIdioma, modo de permissão padrão para sessões novas e adotadas, bloqueio por inatividade (horas até o bot pedir a senha de novo). Também: Verificação rápida — executa um conjunto de verificações (Claude CLI presente, tmux presente, Telegram acessível, …) e mostra o resultado para cada uma; e Teste de ponta a ponta — percorre o caminho completo desde a criação da sessão até a entrega da resposta e reporta cada etapa com a duração.

Registro de auditoriaAções relevantes para a segurança, das mais recentes para as mais antigas: quem fez o quê, e de onde.
10

Tarefas agendadas

As tarefas agendadas executam um prompt automaticamente em um horário definido e entregam o resultado para um número do Telegram. Cada execução cria uma sessão descartável do Claude no modo de permissão bypass; quando termina (ou falha), o resultado é enviado para o número de notificação e a sessão é removida.

Criando uma tarefa agendada

No painel, acesse Agendamentos → Nova tarefa e preencha o formulário. No Telegram, envie /agendamentos, toque em + Novo e siga o assistente — ele pede cada campo em ordem e exibe um resumo antes de salvar.

CampoNotas
NomeAparece nas notificações e no seletor de sessão enquanto a execução está ativa.
PromptO texto injetado no Claude a cada execução.
Diretório de trabalhoCaminho absoluto onde o Claude vai rodar. Deve começar com /.
FrequênciaIntervalo: a cada N minutos (1–10080). Semanal: dias da semana escolhidos em um horário fixo HH:MM.
Número de notificaçãoUm número do Telegram verificado que receberá o resultado. Precisa já estar na lista de permitidos.
Tempo limite1–1440 minutos. Se a execução ultrapassar esse tempo, ela é cancelada e o número de notificação é avisado.
Preservar sessãoQuando desativado (padrão), uma execução bem-sucedida tem o contexto limpo (/clear), é pausada e removida. Quando ativado, a sessão é mantida após o término.

Proteção contra sobreposição

Se a execução anterior de uma tarefa ainda estiver em andamento quando o próximo disparo chegar, o novo disparo é registrado como ignorado e nenhuma nova sessão é criada. Uma tarefa nunca roda duas vezes ao mesmo tempo.

Status das execuções

StatusSignificado
runningA sessão está ativa e o Claude está trabalhando.
waitingO Claude fez uma pergunta. O número de notificação é avisado; responder pelo Telegram ou pelo painel continua a execução.
successA execução terminou normalmente. O resultado foi entregue ao número de notificação.
errorA sessão ficou offline ou o Claude retornou um erro. O número de notificação é avisado.
timeoutA execução ultrapassou o tempo limite. O número de notificação é avisado.
skippedA execução anterior ainda estava em andamento; este disparo foi ignorado.
taken_overUm humano digitou na sessão. O agendador a libera; a sessão passa a ser sua para continuar.
discardedA execução foi descartada manualmente na grade de falhas.

Painel: página de Agendamentos

  • Cartões de estatísticas (janela de 30 dias): total de execuções, sucessos, falhas, ignoradas.
  • Faixa de próximas execuções: o horário do próximo disparo para cada tarefa ativa.
  • Lista de tarefas: executar agora, editar, pausar/retomar e excluir para cada tarefa.
  • Grade de falhas: execuções com falha podem ser reenviadas como nova execução, abertas como sessão ao vivo para concluir manualmente ou descartadas.

Telegram: comandos de agendamento

/agendamentos (aliases /schedules, /programaciones) lista todas as tarefas agendadas. ▶️ significa ativa, ⏸️ significa pausada. Toque em uma tarefa para ver as últimas cinco execuções e obter botões de Executar agora, Pausar / Ativar e Excluir. Toque em + Novo para iniciar o assistente de criação.

As sessões de tarefas agendadas em execução aparecem no seletor de sessão (/trocar, /sessoes) para que você possa entrar nelas a qualquer momento. Se você digitar em uma, a execução é marcada como taken_over e a sessão se torna uma sessão interativa normal.

Conta bloqueada

Se o bot estiver travado quando uma execução agendada terminar, a notificação informa que a tarefa foi concluída e pede que você desbloqueie antes de entregar o relatório completo. Desbloqueie com /senha normalmente.

11

Modos de permissão

Cada sessão roda em um de três modos, escolhido ao criá-la, retomá-la ou adotá-la. O padrão é definido em Configurações → Geral.

ModoComportamento
Perguntar (Ask)Todo pedido de permissão vai para o Telegram e para o painel com botões. Responda de onde estiver; os outros lugares se atualizam.
Auto recomendadoO Claude trabalha sozinho. O classificador de segurança embutido no Claude Code revisa cada ação e bloqueia as arriscadas, inclusive as induzidas por prompt injection (instruções escondidas em arquivos, páginas web ou issues).
Ignorar (Bypass)O Claude roda com --dangerously-skip-permissions e nunca pergunta. Nada revisa as ações dele.

O modo vale a partir do início da sessão. Para mudá-lo, retome a conversa no outro modo: uma conversa que começou num modo pode continuar em outro.

Sobre o modo Ignorar

O Claude vai editar arquivos e rodar comandos na sua máquina sem perguntar. Use só em pastas de confiança, com trabalho que você consiga desfazer, e nunca com conteúdo que você mesmo não escreveu.

Cada pedido de permissão leva um identificador derivado do que foi exibido, e a tela é relida logo antes de a resposta ser enviada. Um botão antigo não consegue aprovar um pedido mais novo; ele é recusado com “não está mais pendente”.

12

Segurança

Quem controla o Tether consegue fazer o Claude rodar comandos como o seu usuário. O projeto parte dessa premissa e coloca várias barreiras na frente disso.

CamadaProteção
Identidade no TelegramO usuário precisa compartilhar o próprio contato, e o número precisa estar na lista de autorizados. Os demais não recebem nada além do pedido para compartilhar o contato.
SenhaExigida depois de cada reinício e após o tempo de inatividade. A mensagem do /senha é apagada. 5 tentativas erradas bloqueiam o usuário por 15 minutos. Travado, o bot não mostra conteúdo.
Configuração obrigatóriaO bot não inicia sem uma senha e pelo menos um número autorizado. O último número não pode ser removido.
Login no painelA mesma senha. Cookie HttpOnly e SameSite=Strict; só um hash do token é armazenado. 5 logins errados bloqueiam o endereço por 15 minutos. Trocar a senha desconecta todas as outras sessões e trava o bot.
RedeEscuta em 127.0.0.1. O cabeçalho Host precisa nomear este servidor (sem DNS rebinding); requisições que mudam estado exigem um Origin permitido e corpo JSON, então formulários de outros sites são rejeitados.
HooksOs endpoints de hooks exigem um token aleatório, lido de um arquivo para nunca aparecer na lista de processos.
Segredos guardadosSenha armazenada com scrypt; token do bot criptografado com AES-256-GCM usando uma chave local. ~/.tether fica com modo 700 e os arquivos dele com 600.
Alcance do ClaudeO tether setup adiciona regras de bloqueio (deny) ao Claude Code para que as ferramentas de arquivo do Claude não possam ler nem editar ~/.tether (token do bot, hash da senha, chave) ou ~/.ssh. Para comandos de terminal também, ative o sandbox do Claude Code (/sandbox); sem ele, a barreira é o classificador do modo Auto.
Execução de processosNenhuma string de shell é montada a partir de entradas. tmux e claude são chamados com listas de argumentos e valores validados; os prompts são colados por um arquivo de buffer privado do tmux.
Registro de auditoriaLogins, desbloqueios, mudanças de token, senha e lista de autorizados, ações de sessão e respostas de permissão ficam registrados.

Recomendações

  • Ative a verificação em duas etapas do Telegram (Telegram → Configurações → Privacidade e Segurança → Verificação em Duas Etapas). A lista de autorizados confia na sua conta do Telegram, então proteja a conta contra clonagem de chip e códigos de login roubados.
  • Use Auto ou Perguntar com conteúdo não confiável. Repositórios clonados, páginas web, issues e documentos podem conter prompt injection. Deixe o modo Ignorar para o seu próprio código, em pastas onde você não se importaria de ver o Claude agir sem supervisão.
  • Nunca exponha a porta 4100 à internet. Para acessar o painel de longe, use uma VPN ou um proxy reverso com autenticação e ajuste TETHER_HOST de acordo.
  • Use uma senha longa. Qualquer pessoa que descubra o nome de usuário do seu bot pode mandar mensagem para ele; a lista de autorizados e a senha são o que a impedem.
  • Troque o token do bot no @BotFather (/revoke) se achar que ele vazou, e cole o novo em Configurações → Telegram.
  • Conclua o assistente logo depois de instalar e mantenha as regras de bloqueio do tether setup.

O Tether não tenta se defender de programas que já rodam como o seu usuário ou como root: eles podem ler ~/.tether e controlar o tmux diretamente. Veja o SECURITY.md para o modelo completo e para saber como relatar uma vulnerabilidade.

Solução de problemas

Comece com tether doctor. Ele verifica os problemas mais comuns.

O bot não responde nada
Ele só responde a números autorizados. Envie /start e compartilhe o seu contato. Se continuar sendo ignorado, confira o número em Configurações → Segurança (dígitos com código do país) e o log do servidor.
“Conflict: terminated by other getUpdates request”
Dois programas estão usando o mesmo token de bot. Pare o outro: só um Tether por token.
As sessões mostram “modelo desconhecido” ou nenhum % de contexto
O repassador da linha de status ainda não está ativo naquela sessão. Rode tether setup e reinicie a sessão.
Depois de reiniciar o computador, todas as sessões estão offline
As sessões do tmux não sobrevivem ao reinício. Envie /trocar, escolha a sessão e toque em 🔄 Reiniciar sessão: ela continua a mesma conversa. Reiniciar no painel faz o mesmo.
Uma sessão que eu mesmo iniciei não aparece
Inicie-a dentro do tmux e use Adotar no painel. Ou use Retomar para reabrir a conversa.
As respostas não chegam depois de um /clear
Deveriam chegar. Se não chegarem, confira se os hooks estão instalados com tether doctor.
O Claude faz várias perguntas de uma vez
Só a primeira pergunta, ou a primeira de uma seleção múltipla, ganha botões. Responda o resto na visualização do terminal no painel, ou com /tela e uma resposta em texto livre.
Fiquei bloqueado no painel
Depois de 5 logins errados, o endereço fica bloqueado por 15 minutos. Em localhost todos os clientes compartilham 127.0.0.1, então espere ou redefina a senha com tether passwd.
Esqueci a senha
Rode tether passwd na máquina.
Onde ficam os logs?
journalctl --user -u telegram-claude-tether -f para o serviço, ou o terminal onde o tether está rodando. Defina TETHER_DEBUG=1 para mais detalhes.

Contribuições e traduções

Issues e pull requests são bem-vindos. Pull requests pequenos e focados são os mais fáceis de revisar.

Desenvolvimento
$ npm install
$ npm run dev        # servidor em :4100 (recarrega), painel em :5173
$ npm test           # testes unitários
$ npm run typecheck  # servidor + painel

Para manter uma instância de desenvolvimento separada de uma instalação real, rode TETHER_HOME=/tmp/tether-dev TETHER_PORT=4200 npm run dev:server.

  • O contrato primeiro: se um endpoint ou uma mensagem mudar, atualize src/shared/api.ts e os dois lados no mesmo PR.
  • Nunca monte strings de shell a partir de entradas do usuário. Use execFile com listas de argumentos.
  • Mudanças sensíveis à segurança devem explicar o modelo de ameaça na descrição do PR.
  • Adicione um teste para qualquer lógica de parsing ou de segurança.

Adicionando um idioma

  1. Copie locales/en/ para locales/<código>/ (por exemplo fr, de, zh-CN).
  2. Traduza bot.json e web.json. Mantenha os {{placeholders}} e as tags HTML.
  3. Adicione o código a SUPPORTED_LOCALES em src/server/settings.ts, à lista de idiomas em web/src/lib/i18n.ts e aos rótulos do /lang do bot.
  4. Se quiser, adicione apelidos traduzidos dos comandos em src/server/bot/bot.ts. Comandos do Telegram só podem usar a–z, 0–9 e _.

Rode npm test: um teste confere se todos os idiomas têm as mesmas chaves do inglês. Veja o CONTRIBUTING.md e o ARCHITECTURE.md para mais detalhes.
